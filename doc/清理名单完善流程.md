# 清理名单完善流程

给某个工具（Codex / Claude Code / Cursor / 新工具）补全或校正 `CleanTarget` 时，按本流程做。目标：名单上的项**真能清到**，该有的**不遗漏**，风险与默认勾选**和用户预期一致**。

相关代码：

- 名单数据：`src/main/kotlin/dev/cxclear/profiles/Profiles.kt`
- 风险与匹配模型：`src/main/kotlin/dev/cxclear/model/Model.kt`
- 路径解析与冻结计划：`src/main/kotlin/dev/cxclear/scan/Scanner.kt` 的 `resolveBase` / `resolveTarget` / `DeletionPlan`
- 计划校验与逐条删除：`src/main/kotlin/dev/cxclear/clean/Cleaner.kt`（禁止重新解析 target 或递归遍历）
- 默认勾选落地：`src/main/kotlin/dev/cxclear/ui/components/MainContent.kt`（必须读 `CleanTarget.defaultSelected`，不能只看 `Risk.SAFE`）

---

## 0. 原则（动手前先对齐）

1. **优先只加数据。** 新工具 / 新清理项尽量只改 `Profiles.kt`。现有 `MatchKind` 装不下时，再扩展通用能力（且对所有工具有用）。
2. **扫描冻结、清理只执行计划。** 路径只在 Scanner 展开一次；Cleaner 必须核对文件身份并只删 `DeletionPlan` 中的条目，不能重新匹配或递归。
3. **软链接不跟随；运行中工具不清；删除容错不中断；进度报实测字节。**
4. **SAFE ≠ 一定默认勾。**
   - `Risk.SAFE`：不丢用户数据，工具可重建。
   - `Risk.OPTIONAL`：删了不可恢复（会话、用户规则等），绝不能默认勾。
   - 重建很贵（大体积重下、会暂时搞挂功能）的 SAFE：保持 `SAFE`，显式 `defaultSelected = false`。
5. **拿不准就不提供，或标 OPTIONAL。** 安装目录、登录态、主配置、用户规则默认不进名单。

---

## 1. 读现有名单

1. 打开 `Profiles.kt` 里对应的 `ToolProfile`。
2. 记下每一项：`id` / `label` / `relPath` / `kind` / `entryType` / `risk` / `defaultSelected` / `baseDir`。
3. 看 `baseDir`、`spaceDirs`、`processNamePrefixes`、`protectedPaths`、`subtitle`：有没有漏掉的数据根、运行进程或永久保护目录。
4. 读配置文件（若有，如 `config.toml`）里写死的路径——常能发现名单外的根目录。

---

## 2. 吃透本机真实目录

在**用户本机**把工具相关根目录摸一遍，不要只信文档或记忆。

### 2.1 定位根目录

常见候选（按工具增减）：

- `~\.<tool>`（如 `~/.codex`、`~/.claude`、`~/.cursor`）
- `%APPDATA%\...`、`%LOCALAPPDATA%\...`（安装与 Electron 数据）
- `~\.cache\...`（运行时依赖）
- `~\Documents\...`（无项目会话工作区等，多半是用户产物，慎入名单）

确认环境变量：`USERPROFILE` / `APPDATA` / `LOCALAPPDATA` / 工具自己的 `*_HOME`。

### 2.2 量体积、列结构

对每个根目录：

1. 顶层条目按体积排序。
2. 对大头目录再下钻 1～2 层（必要时对比哈希，识别「安装目录副本」）。
3. 区分：**安装目录** / **可重建缓存** / **用户数据** / **密钥与配置**。

记录一版「路径 → 约体积 → 用途猜测 → 是否已在名单」。

### 2.3 对照配置与进程

- 读 `config.toml` / `settings.json` 等，看 `source =`、绝对路径是否指向即将清理的目录。
- `processNamePrefixes` 是否能命中 CLI、GUI 和 helper 进程；目标工具运行时必须整批阻断，不能依赖文件锁碰运气。

---

## 3. 逐项核对「现有名单能否真清」

对每一条 `CleanTarget`，直接调用 Scanner 生成冻结的 `DeletionPlan`（或跑一次扫描看结果）：

| 核对点 | 问题示例 |
|--------|----------|
| 路径是否存在 | 死项（如早已废弃的 `sqlite/`） |
| glob / STALE 是否命中预期文件 | `foo-*.exe` 漏掉无版本号的 `foo.exe` |
| `entryType` 是否正确 | FILE/GLOB 绝不能接受同名目录；历史版本目录必须显式用 DIRECTORY |
| DIRECTORY vs DIRECTORY_CONTENTS | 误删目录本身，或只该清子文件却整目录清空 |
| STALE_VERSIONS | 是否误删正在用的最新份；是否误伤同目录其它大文件（如 `codex.exe`） |
| 文案是否诚实 | 写「插件缓存」实际只清了很小一块，大头在隔壁目录 |

产出：

- **能清**：保留或改文案。
- **半对**：改 `relPath` / `kind` / 收窄范围（例如只清 `sandbox*.log`，不要整清 `.sandbox`）。
- **死项**：删掉或保留作兼容并在 description 写明「多数机器已不存在」。
- **危险**：移出名单或改为 OPTIONAL，并写清后果。

---

## 4. 找遗漏

结合体积排序，问：

1. 大头目录是否完全没进名单？
2. 是否只清了子树的一小角（如只清 `plugins/cache`，漏了 `plugins/.plugin-appserver`）？
3. 是否有目录外的第二根（cache / AppData）应进 `spaceDirs` 与独立 `CleanTarget.baseDir`？
4. 文档或 issue 提到、本机没有的路径：可作为兼容项，但不要写成「一定有」。

**刻意不纳入**（除非有很强理由）：

- 安装目录整树
- `auth` / 主配置 / 安装 ID
- 会话主库、记忆库、用户规则、登录态存储
- 用户工作区（如 `Documents\Codex` 下的 clone）

---

## 5. 定风险与默认勾选

对每个拟保留/拟新增项填两列：

| 维度 | 判断 |
|------|------|
| 丢用户数据？ | 是 → `OPTIONAL` 或不上名单 |
| 重建成本 | 本地秒级重建 / 大体积重下 / 需再同步且短暂不可用 |

规则：

```
不丢数据 + 重建便宜     → SAFE，defaultSelected 默认 true
不丢数据 + 重建很贵     → SAFE，defaultSelected = false
会丢且不可恢复         → OPTIONAL（默认不勾）
说不清                 → 不上名单，或 OPTIONAL
```

说明文案（`label` / `description`）应写清：

- 清的是什么（具体到目录角色，避免空泛「缓存」）
- 删了会怎样（重建方式、是否要重下、是否要先退出应用）
- 明确不碰什么（若容易误解）

---

## 6. 落代码

1. 改 `Profiles.kt`：增删改 `CleanTarget`；多根时补 `spaceDirs` / `subtitle` / `baseDir`。
2. 按占用大致排序（大的靠前），方便用户从上往下勾。
3. UI 分类关键字若靠 `target.id` 子串（见 `MainContent.buildCategories`），新 `id` 要能进对的桶（如含 `plugins` / `cached` / `runtime`），或扩展关键字列表。
4. **确认默认勾选链路**：扫描结束后必须使用 `defaultSelected`，禁止写死 `risk == SAFE`。
5. 为新 profile 声明 `processNamePrefixes`；确定的数据库、会话主库等加入 `protectedPaths`。
6. `./gradlew test` 验证。注意：在 Cursor Agent 沙箱里 `GRADLE_USER_HOME` 可能被指到临时目录，导致重复下载 Gradle；本机验证时用用户真实 `~/.gradle`。

---

## 7. 验收清单

- [ ] 对本机跑一遍扫描：新项有体积、路径正确
- [ ] `defaultSelected = false` 的项扫完后**未勾选**
- [ ] SAFE 默认真勾的项已勾选；OPTIONAL 未勾选
- [ ] 模拟/确认 STALE 只删旧份、保留最新
- [ ] 收窄过的目录不会误删状态文件（marker / secrets / ACL 等）
- [ ] FILE/GLOB 不接受目录；STALE 在 mtime 并列或读取失败时全部保留
- [ ] 扫描后新增文件不进入删除计划；已扫描文件被替换或修改时，Cleaner 拒绝删除并要求重扫
- [ ] `DeletionPlan` 的 tool/target 身份与清理请求不一致时整项拒绝
- [ ] 工具进程运行时清理被阻断；永久保护路径无法通过父目录规则绕过
- [ ] `spaceDirs` 合计与磁盘直觉一致（安装目录仍不计或另说明）
- [ ] 文案与真实行为一致

## 附录：MatchKind 选用速查

| kind | 用途 |
|------|------|
| `DIRECTORY` | 整目录删掉（含目录本身） |
| `DIRECTORY_CONTENTS` | 清空内容、保留目录壳 |
| `FILE` | 单个文件 |
| `GLOB` | 目录下按文件名 glob 一批 |
| `STALE_VERSIONS` | 同 GLOB，但按 mtime 保留最新一份 |

路径段里单独的 `*`：展开为该层每个非符号链接子目录（见 `expandPathPattern`）。
